# 잡앤킬 취업·면접 캐러셀 운영기준 v2

2026-10-21 개편안. 대상은 첫 취업을 준비하는 신입 지원자다. 대학 신입생·모든 계약직·특정 직무 종사자로 일괄 가정하지 않는다. 이번 산출물은 주제 풀과 시스템 교정이며 새 캐러셀 이미지가 아니다.

## 1. 원형·근거·후크를 분리한다

질문 원형은 독자가 알고 싶은 문제를 담는 불변 필드다. 후크는 별도 필드이며 바꿔도 원형을 덮어쓰지 않는다. 이번 새 후보 150개의 원형은 SHA-256 manifest로 고정했다. 과거 150개 원본은 아직 특정되지 않았으므로 같은 데이터라는 주장은 금지한다. 찾으면 원본 파일 바이트·원문·ID·버전을 별도 보존하고 대응표를 만든다.

각 주제에 질문·대상·근거 URL·열람일·근거 범위·한계·직접 질문/유사 질문/원칙 참고/미검증 등급·편집 우선순위·답변 4단계·가상 연습·후크 5안·선정 제목·6장 기획·사용 이력을 둔다. 검색 결과 요약만으로 본문 확인을 대신하지 않는다. 커뮤니티 질문 하나는 고민의 존재 증거이며 인기·대표성·합격 효과 증거가 아니다. 회사의 현행 채용 조건은 해당 공고 원문과 확인일이 필요하다.

현재 공개 근거 28개는 기관·대학·취업 플랫폼·커뮤니티 자료다. 질문별 등급은 direct 12 / close 49 / principle 71 / unverified 18이다. 모두 실제 검색 수요가 검증된 인기 150선이라고 부르지 않는다. 우선순위 1은 45개이며 직접 6·유사 19·원칙 20으로 구성한다. 근거가 미확인된 18개 질문은 조사 대기 상태다.

후크는 상황 공감·놓친 판단·답변의 빈칸·전후 변화·실천 이익 등 서로 다른 각도에서 5개 작성한다. 질문 뒤에 동일한 접미 문구를 붙인 5개는 반려한다. 구체성·대상 관련성·호기심·정직성·명료성을 각 0~2점으로 비교하되 점수는 편집 휴리스틱이다. 고득점이나 짧은 문장만으로 최종 승인하지 않는다. 근거 없는 합격 수·탈락률·면접관 심리·비밀·기한·조회수는 금지한다. 다른 강점 표현을 무조건 나쁘다고 깎아내리지 않는다.

## 3. 의미 있는 6장과 답변

1. 누구의 어떤 고민인지와 읽고 얻을 변화를 명료하게 보여준다.
2. 질문 원형과 흔히 할 법한 약한 답변을 대비한다. 약한 답은 실제 독자 인용으로 위장하지 않는다.
3. 그 답에 빠진 행동·선택 이유·근거를 설명한다. 면접관의 속마음을 지어내지 않는다.
4. 실제로 바꿀 행동과 준비 순서를 제시한다. 같은 사례의 사실을 유지한다.
5. 4장의 사실만으로 자연스러운 답변을 보여준다. 정답 없는 조건형 질문은 조건·대안을 말한다.
6. 독자가 자기 경험으로 채울 빈칸 또는 실천 1개와 자연스러운 잡앤킬 팔로우 안내를 둔다.

모든 경험을 거창한 개선 성과로 바꾸지 않는다. 친절·성실·관찰·질문하기도 실제 장면과 행동이 있으면 소재가 된다. 수업·동아리·알바·봉사·개인 프로젝트를 쓸 수 있다. 없는 권한·수치·팀 성과를 만들거나 실제 안 한 행동을 면접에서 말하도록 유도하지 않는다. 가상 예시는 자기 실제 경험으로 바꿔 쓰는 연습용이며 캡션·제작 기록에 성격을 밝힌다. 카드마다 상투적인 고지를 반복하지 않는다.

사진 7개와 표지 10종은 기존 실물 자산을 확인했다. 재사용과 신규 생성을 구분하고 사진을 채용 성과의 증거로 쓰지 않는다. 표지 사진 비율만 지켜도 좋은 디자인이 되는 것은 아니다. 장별 정보·한글 큰 제목·검정/흰색 대비·제한된 형광 강조·손/도구 크롭·모바일 읽기를 함께 본다. 10개 번호를 채우려고 내용에 안 맞는 배치를 고르지 않는다.

## 5. 버전·중복·충돌

기존 Library revision 128은 73건 retained 사본이며 실제 게시 확인과 다르다. ZIP의 revision 15는 오래된 대장이다. 기존 본체를 새 후보로 교체하지 않는다. 원문 수정이 필요하면 원형을 남기고 새 편집 필드·parent_version을 추가한다.

읽기→SHA256/버전 확보→독점 잠금→잠금 안에서 재읽기→revision+basehash 비교→새 이벤트 독점 생성→flush/fsync→재검증 순서다. 불일치면 새 자료를 읽고 병합한다. lock 파일을 자동 삭제하지 않는다. 로컬 잠금은 원격 Library의 분산 CAS를 대신하지 않는다. 원격 조건부 버전 저장이 없으면 새 이름/새 Page로 보존하고 기존 본체 갱신은 보류한다.

질문 150개 내부 11,175쌍 문자 비교에서 66쌍을 의미 검토했다. 58쌍은 구분 유지, 8쌍은 통합 후보이며 연결 성분 6개를 semantic_overlap_groups.json에 둔다. 이는 나머지 11,109쌍의 의미 중복 부재를 증명하지 않는다. 통합 후보는 원문 삭제 없이 같은 작업 묶음/발행 묶음에서 함께 선정하지 않는다. 실제 서버의 그룹 잠금 연동은 별도 구현 대상이다.

## 6. 한국어와 im-not-ai

정식 스킬 설치·직접 호출·공개 보조 스크립트 실행·공개 규칙 적용을 서로 구분한다. 원문 버전·커밋·라이선스·파일 지문·실행 명령·종료 상태를 남긴다. 공개 보조 스크립트가 통과해도 의미·신입 적합성·후크 효과를 검증한 것이 아니다. 국립국어원 규범·표준국어대사전은 실제 조회한 범위만 조회했다고 적는다.

윤문은 주어와 서술어·조사·지시 대상·시제·원인·행동·결과·말하기 자연스러움을 본다. ‘기준으로 말하세요’에서 무엇의 기준인지, ‘그것’이 무엇인지 처음 읽는 독자가 알아야 한다. 직접 인용·기간·수치·회사명·의도·확신 강도는 보존한다. 변경률은 경고 신호일 뿐 성능 지표가 아니다.

## 7. AB 검증과 지속 학습

발행 승인 전에 가설·변수 1개·주 지표 1개·보조 지표·관측 창·제외 조건·중단 조건을 기록한다. 예: 같은 주제 표지의 질문형과 방법형이 저장률에 차이가 있을까. 유기적 게시 2개는 독자가 무작위 배정되지 않으므로 탐색 비교로만 해석한다. 피드 중복 피해가 크면 먼저 타깃 독자에게 제목의 대상/얻는 정보를 말하게 하는 이해도 검사를 한다. 시행하지 않으면 미실시다.

실제 발행 시각 기준 24시간과 7일에 도달·노출·저장·공유·댓글·프로필 방문·팔로우를 제공되는 범위에서 관측한다. 저장률=저장/도달, 공유율=공유/도달이다. 도달 0이면 비율은 null, 미제공도 null이며 관측 0과 다르다. 창별 누적 지표를 더하지 않고 중복 집계·정의 변경을 기록한다. 가능하면 최근 동일 형식 게시물의 중앙값과 동일 발행 나이로 비교한다. 샘플 수와 기간이 부족하면 승자라고 하지 않는다. 사전 최소 표본은 실제 기준 저장률과 검출할 차이로 정하고 관측 전 임의 성공 수치를 쓰지 않는다.

학습대장은 주제 ID·원형 버전·후크/원고/이미지 해시·가설·실제 노출·관측 창·혼란 요인·결론·다음 수정으로 연결한다. 저장이 높다는 이유만으로 과장 표현을 되살리지 않는다. 이번 실적 CSV는 헤더만 있고 실제 지표는 0건이다.

## 8. 실제 실행과 자동화

기존 ChatGPT 예약은 ‘잡앤킬 캐러셀 주제와 품질 지속 개선’으로 수정했다. 현재 시간 단위 예약·다음 실행 2026-10-21 04:00 KST를 화면에서 확인했다. 한 실행에서 최대 10개 질문씩 조사·편집·검수·수정 루프를 이어 가고 체크포인트를 남기도록 지시했다. 일시 중지나 무한 자기 호출이 아니다. 실제 지속 실행 시간·재개 성공·계정 한도는 아직 검증하지 않았다.

[GitHub 공식 schedule 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule): 최소 5분 간격이지만 기본 브랜치에서만 실행되고 지연·누락 가능성이 있다. 이번 PR의 검사 워크플로는 push/PR/수동 검증이며 주기적 콘텐츠 생성은 활성화하지 않는다. GitHub 코드가 실제 AI 편집을 자동 수행하는 것으로 보고하지 않는다.
